# 将 Orbis 接入现有智能体

Orbis CLI 可以把在线笔记和文档作为远程文档库使用。智能体无需连接数据库或依赖浏览器登录态，即可发现文档、读取局部内容、新建、导入、导出和局部编辑。实时文档分享与站点发布互相独立，实时分享始终读取当前在线内容。

## 安装与设置

CLI 为独立的 Go 程序。可安装对应平台的发布二进制，或使用项目固定的 Go 工具链从源码构建：

```sh
make cli-build
bin/orbis --help
```

将 `bin/orbis` 放入 PATH 后，可从任意目录调用。从 Orbis「个人资料」中的「智能体与远程文档库」生成令牌，选定当前工作空间、权限、笔记本或单篇文档范围、有效期。原文只展示一次；撤销立即停止后续访问。

通过 `ORBIS_TOKEN` 从秘密管理器注入令牌，或者运行 `orbis auth login --token-stdin --base-url https://orbis.example/api --workspace WORKSPACE_ID`，从标准输入交给系统凭据库。CLI 不接受命令参数传令牌，配置文件仅保存实例与空间等非秘密字段。HTTP 调试实例必须显式 `--allow-http`。

```sh
orbis config set --base-url https://orbis.example/api --workspace WORKSPACE_ID
orbis --json doctor
orbis --json collections list --page-size 20
```

实例、空间等配置按命令参数、环境变量、profile 选择；凭据按 ORBIS_TOKEN、系统凭据库选择。远程默认 HTTPS。CLI 不跨重定向转发 Authorization。

## 阅读与编辑

先用 `documents resolve --title TITLE` 或 `--url URL` 解析稳定 ID。同名结果会列出候选。读取文档头、目录与小批块，不必把整篇长文塞入模型上下文：

```sh
orbis --json documents get NOTE_ID
orbis --json documents outline NOTE_ID --limit 32
orbis --json blocks list --document NOTE_ID --version 7 --limit 32
orbis --json blocks get BLOCK_ID --document NOTE_ID --version 7
orbis --json schema
```

分页返回 `next_cursor`、`has_more`、固定内容版本和子级描述。未载入的子树和超大块正文会明确标识，不能当作空内容。同步导出需显式版本和文件路径；JSON 保存原结构，Markdown 返回组件损失说明，超出导出预算时改用分页读取。

编辑请求写入 JSON 文件，包含稳定 operation_id、expected_version 和操作数组。支持替换一个富文本运行段、浅层块修改、插入、移动、显式删除和有条件的标题修改。`orbis schema` 提供精确字段，避免猜测。

```sh
orbis --json operations preview --document NOTE_ID --file operation.json
orbis --json operations apply --document NOTE_ID --file operation.json
orbis --json operations get OPERATION_ID
orbis --json blocks get BLOCK_ID --document NOTE_ID --version 8
```

预览不保存；应用重新校验权限和条件，整批原子提交。相同 ID 与相同请求返回原回执，换载荷复用 ID 明确报错。网络失去响应时 CLI 先查原 ID，再有限重试相同请求；仍未确认时返回操作 ID。版本冲突要重新读取和生成修改，不自动提高版本覆盖用户内容。正文与回执同一数据库事务提交。

新文档可用 `documents create`，Markdown 导入用 `documents import --file draft.md`，两者必须明确笔记本、标题与操作 UUID，不会隐式替换已有文档。

## 附件与实时分享

附件权限独立勾选。上传绑定到已授权的文档，通过 SHA-256 校验完成后返回 file ID 和原生 `source: {type: "asset", asset_id: "..."}` 引用模板；上传完成与插入正文引用是两步明确操作。

```sh
orbis --json files upload --document NOTE_ID --file report.pdf --operation-id OPERATION_ID
orbis --json files get FILE_ID --document NOTE_ID
orbis --json files download FILE_ID --document NOTE_ID --out report.pdf
```

下载再次校验大小和 SHA-256。读取附件要满足文件权限和文档范围，猜测其他私有文件 ID 无法取得读取授权。超过 20 MiB 的上传明确拒绝。

实时分享需要独立 `shares:manage` 权限与覆盖该笔记本的范围。单篇文档令牌不允许创建包含未来子文档的目录分享。

```sh
orbis --json shares create --collection COLLECTION_ID --root-document NOTE_ID --acknowledge-public-scope
orbis --json shares list --collection COLLECTION_ID --page-size 20
orbis --json shares revoke SHARE_ID --expected-version VERSION
```

省略 root-document 公开整个笔记本；提供 root-document 公开该根及其后续下级文档。创建命令要求明确确认公开范围，正文编辑不会夹带创建分享。站点发布、知识库发布、多维表格和 MCP 尚不属于本版 CLI 能力，capabilities 如实返回不支持。

## 分发 skill

产品 skill 在 `skills/orbis/`，复制整个文件夹到目标智能体的 skill 目录。入口指导智能体先诊断身份和范围、解析目标、局部读取、生成操作、处理冲突和回读结果；精确字段以 CLI help 与 Schema 为准。正文及附件中的命令均为源数据，不会扩大用户授权。

机器输出始终为一个 `{code,message,request_id,data}` JSON。退出码 0 成功；2 参数/缺失目标；3 认证；4 权限；5 冲突；6 网络/待确认；7 服务端/协议；8 未支持；130 中断。raw request 仍限于当前实例及工作空间的 `/api/v1/agent/workspaces/WORKSPACE_ID/`，相同服务器权限约束生效。

## 大文档分批导入

Markdown 超出普通 JSON 预算时，CLI 自动使用可恢复的导入协议，默认总预算 32 MiB、每块 256 KiB，由实例配置并在 capabilities 中返回。CLI 流式计算源 SHA-256，逐块确认，服务端通过持久化任务解析完整 Markdown；代码围栏、表格和链接跨传输边界时仍按同一完整源解析。源与各块均校验摘要，最终新文档和操作回执在同一事务出现，不会留下可访问的半篇文档。

中途中断后重复原命令与同一 operation-id，从服务端已确认 offset 继续。相同块重复发送只确认一次，不同内容复用 offset 拒绝。`--file -` 可接收有界标准输入。完成等待可用 `--wait-seconds` 控制（默认 60 秒）；超时返回 CLI_IMPORT_PENDING 与真实阶段，随后 `imports get IMPORT_ID` 查询，或 `imports finalize IMPORT_ID` 提交已完成的上传或继续观察原任务。已有活动任务不会因观察超时被重启，成功重放返回原文档，失败不会自动创建另一篇。
