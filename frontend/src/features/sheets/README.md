# Sheet workspace

- `SheetWorkspace` composes views, schema actions and document chrome. `use-sheet` owns queries and exact pending write receipts; an uncertain response must be retried with its original operation ID and payload.
- `SheetGrid` owns cell editing, rectangular selection and checked record IDs. Cell clipboard encoding and record duplication live in `record-actions`; context menu presentation lives in `SheetRecordMenu`.
- Row numbers, drag handles, checkboxes and record expansion share the sticky gutter. Pointer controls appear on hover or focus; touch targets remain visible. Space expands the active record; F2 edits its cell. Shift+F10 opens the active cell's record menu.
- `FieldManager` drafts visible column order and visibility until Apply. Its handles support pointer drag and arrow keys; the field menu also offers move controls. A view always retains one visible field. `definition` updates column references consistently across views, including insertion beside reordered columns.
- Manual record order is available in an unfiltered, unsorted, ungrouped grid. Relative inserts and moves use optional `before_id`/`after_id` record patches. The server commits ordering and the idempotent receipt together under an exclusive schema lock; ordinary record edits retain shared schema locking. A separate ordering revision invalidates old pagination cursors after relative placement while preserving cursor compatibility for ordinary edits.
- Migration 28 changes the position identity column to `GENERATED BY DEFAULT`, allowing transactional placement while retaining existing rows and sequence-based appends. Relative writes persist integer ranks. Rolling back the migration restores `GENERATED ALWAYS` without changing record content or IDs.
- Public form delivery remains separate from form editing. Creation and collection entry points follow the existing release feature flag.

Run frontend type checks, unit tests and production builds, then the sheet browser journeys. Backend ordering, rollback, receipts, isolation and concurrent writers are covered by the PostgreSQL sheet integration suite, including `-race` runs.
